`HttpClient` no longer rejects with `SyntaxError: Unexpected end of JSON input` for a success response without data. A 204 or 205 of any content type, a JSON response with `content-length: 0` and a JSON response with an empty or whitespace-only body now resolve to the same `{ success: true, status }` envelope that a response without a content type already returned, without reading the body for 204, 205 and `content-length: 0`. JSON bodies are read with `text()` and `JSON.parse`, so valid JSON resolves as before. Decode failures on a success status now go through the client's normal failure path: a non-empty body that is not valid JSON, or a body read that rejects, rejects with an `HttpError` with status 500 carrying the original error and calls `onError` once with `transport: true`; an HTML answer on a status other than 204 or 205 still rejects with "Unexpected HTML response from server" and now also calls `onError` with `transport: false`. `createHttpFailureReporter` therefore reports invalid JSON once as `source: "http-client"` with the URL and method, instead of `attachQueryErrorReporting` reporting the raw `SyntaxError` as `source: "react-query"`, so these faults move to a different Rollbar grouping.
